# Context Orb 重设计 V1.1

2026-09-06。用户已确认球内风险、外环容量、一键处理，并确认新会话核对交接后自动继续；本轮授权方案复审达到 9/10 后实现。设计评分不表示运行时验收通过。

## 复审方法

固定权重：视觉辨识 20、操作可预期 25、状态真实性 25、交接可靠性 20、性能与可访问 10。总分至少 90，且不得存在改错任务、虚构成功、重复续作的未闭合设计缺口。初次独立评分为 82/100（16、21、20、17、8）。以下是针对扣分点的完整修订；重新评分另行记录，不能预填达标分。

实际二次独立复审为 **91/100**（18、23、24、18、8），已读取全文和视觉样稿。当前可实施的真实 UI、状态与准备/详情动作闭合了三类否决缺口；真实压缩、创建和续作未接通，不在已通过功能验收范围。保留扣分：真实 92px 可辨性、peek 时序与短屏优先级、一致的未接入文案、未来操作 ID 与宿主事件对应、真机性能和对比度。

## 视觉与空间合同

视觉样稿：[光带球核与独立外环](assets/orb-v05-direction.png)。这是 ImageGen 生成的方向参考，非真实应用截图。实现保留光带体积、深色球壳、独立容量环和精简面板；去除样稿中未定义的风险刻度条。文本、计量与焦点由原生界面绘制，不使用位图 UI。

- 原生紧凑窗口保留 92×92；球核约 70px，容量环外径 84px，总绘制范围不超过 90px。焦点轮廓不借用容量环。
- 深色半透明球壳与两条有体积感的光带。青蓝表示所列依据一致；局部琥珀干扰表示待核验；有证据的偏差使用珊瑚色错位与分叉；未知使用独立的低饱和雾状纹理和问号。颜色、形状和文字并存。
- 用户补充明确要求动态 liquid orb：全部纹理由代码实时生成，液态形状持续变化，四态以 800ms 权重过渡衔接，中途切换从当前形态继续。应用不以图片或预录视频作为动画；样稿仅作方向参考。
- 外环只表示上下文占用，固定起点，不旋转充当进度动画；未知显示虚线，历史读数明确标示时点，不当作当前容量。
- 球外的 peek 是同一原生窗口中的独立预览状态，不从 92px 容器向外越界绘制。预览与完整详情都有明确的请求尺寸，复用原生定位保持球的全局坐标并向可用屏幕内展开；序列化尺寸变更，旧回执不能覆盖新布局。
- 悬停或键盘聚焦显示 peek，内容为固定会话、当前可执行动作、容量与风险依据时点。peek 不抢键盘焦点；右键或上下文菜单键打开完整详情。开始拖动时取消预览计时，结束拖动不执行动作。
- 第一次出现保留简短的操作提示；完整详情中提供相同操作，不把功能只藏在悬停或右键手势里。

## 指标与动作合同

- 文件条件 FAIL 表示工程检查偏差，只引导查看对应证据，不代表已检测到语义污染，也不授权交接。高风险自动交接需要独立、当前、匹配任务身份且支持干预的依据；现有文件收据不具备此资格。
- 压缩次数、年龄、容量都不提升风险级别。压缩后保留上次风险与采集时点，提示复查；新的实际检查才更新结论。新会话在核对前保持未评估，创建成功不能变成绿色。
- 当前 native hooks 没有真实容量读数。无读数显示未知，不借用 demo、累计消耗或账户额度。压缩后只有新占用读数能改变容量环。
- 推荐动作必须先经过宿主能力检查。没有可用检查接口时显示“准备检查指令”；没有压缩接口时只显示“查看压缩指引”；没有交接接口或适用证据时只显示“整理交接简报”。这些动作不得显示执行中、已压缩、已交接等运行反馈。
- 原生与明确标注的演示数据必须隔离。演示即使提供动作预演也只能使用隔离的虚构状态；不能把演示能力带入原生。
- 能力齐备时：未知/待核验→检查；依据一致且容量充足→详情；依据一致且存在可靠容量压力→压缩；可靠偏差证据且交接条件成立→交接。没有校准依据时不能仅按颜色或百分比开放自动交接。

## 意图与会话身份

- 位置吸附不改变手动固定的任务；最近活跃不能替代当前选中。peek 和详情始终显示操作目标。
- 每次按下锁定任务身份、动作种类与其依据；释放前重新核对。变更时撤销本次意图并说明，不能替换动作或目标。
- 原生拖动开始/结束请求可能延迟。等待期间抑制另一手势和快捷操作；任何被确认移动的手势都不能触发主动作。
- 正在处理时点击只查看当前进度。键盘、鼠标、详情按钮走同一动作分发；不能绕过能力与身份检查。

## 交接与取消合同

该部分为待宿主接通后的执行合同，目前不得伪装为已可用。

- 一次操作记录源任务、目标任务（取得后固定）、指定下一步、依据版本、当前阶段与已确认结果。阶段为等待交接点、整理交接、创建目标、核对、开始续作、完成/需处理。
- 运行中的源任务只在宿主可确认的交接点停止续作；源任务尚未确认停止、或存在结果不明的写操作时不得启动目标续作。仅凭一个历史 Stop 事件不能证明当前源任务空闲。
- 用户更换固定任务或依据失效时取消尚未执行的排队请求。取消已发送操作仅在宿主确认后才能宣称取消成功；Escape 只是关闭面板。
- 创建目标或开始续作的回执不明时先核对已有操作记录；不得自动重新创建或重发下一步。恢复功能重用已有目标和阶段。
- “核对通过”要求目标任务明确确认有效目标、约束、工作状态和指定下一步；影响执行的未决项必须解决或转为用户问题。仅收到交接文本不算通过。
- “已接续”要求目标任务已开始指定下一步的宿主事件；源任务随后保持停止续作。旧任务保留查看入口，不自动归档或删除。
- 交接保留用户当前授权范围。若任务仍限定只讨论，自动续作继续讨论，不自行开始实现。

## 性能与可访问合同

- 动效仅用于球核且独立于宿主轮询。隐藏、减少动态效果或用户关闭动效时停止装饰更新；拖动时暂停装饰动画，保持当前状态形状与文字。
- 用同一目标移动轨迹比较动效开启/关闭时的跟随延迟与丢帧；静止渲染实验不冒充真实窗口跟随通过。
- WebGL 球核上限为 70px × DPR 2，使用常驻 canvas 和独立动画循环，不逐帧更新 React 或查询宿主。GL 不可用或缺少所需精度时保留代码绘制的静态兼容状态，此降级不等于动画通过。
- Enter/Space 执行明确的主动作，上下文菜单键打开详情，Escape 收起且恢复球体焦点。屏幕阅读器可读目标、风险、容量、操作及不可用原因。
- 检查四个布局角、短屏、负坐标、高 DPI、展开/预览/收起快速切换、原生尺寸回复乱序、连续点击与拖后释放。

## 上线验收与当前范围

先实现并验证新球体、独立指标、同窗 peek、详情及能力感知的动作。真实容量、语义干预依据、桌面宿主控制分别验收；任一缺失都必须在产品中表现为不可用或准确命名的准备动作，不能把设计分当功能已上线。

自动化验收至少覆盖：低风险高容量不变成高风险；文件 FAIL 不触发交接；未知不显示 0%；压缩不清风险；旧意图不改目标；无能力不伪装执行；创建/续作回执不明不重放。尚未接通的真实接口保持关闭，后续补齐运行验收后才启用。
