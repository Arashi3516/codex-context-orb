# 路线与验收门槛

版本：0.1.0 · 2026-09-06

目标是在 Windows 与 macOS 上，以安静的悬浮球提示用户当前会话的上下文风险，并帮助审阅交接到新会话所需的信息。里程碑按可验证结果推进，不以演示效果代替真实接入。

公开仓库目标：[Arashi3516/codex-context-orb](https://github.com/Arashi3516/codex-context-orb)。源码发布、可下载安装包和官方目录上架各自记录验收结果。

## 0.1.0：框架与可运行设计

当前范围：

- 独立的 Tauri 2 桌面壳与 React/TypeScript 界面基础。
- 明确标识的浏览器演示场景，展示悬浮球、详情卡片、状态、静音与交接模板交互；系统通知尚未接入。
- 可独立测试的规则；未知输入不能得到健康结果。
- 一个有效 Codex 插件包，包含 `context-health` skill 和异步元数据 hook 适配器。
- 每会话一个本地原子快照；无正文存储、无网络传输、无自动会话操作。
- 架构、分发、UIUX 与验证文档。

完成本阶段时，报告中分别列出实际跑过的前端、插件与原生验证。只读 collector 的合成输入测试通过，不能写成“已在两个平台接入当前 Codex 会话”。本阶段不交付自动前台绑定、真实容量测量、语义杂乱判断或官方上架结果。

## 下一阶段：先证实会话身份和数据来源

1. 在 Windows x64、macOS arm64 与 macOS x64 分别跑桌面壳及真实 hook trust/dispatch 测试，记录具体 Codex 版本。
2. 证明会话 ID 能与用户明确选中的界面对应。前台信号不可得时保留手动固定和未知状态。
3. 为真实上下文占用选择可追溯数据源，校验会话、模型窗口、更新时间及压缩后的变化；缺失值继续未知。
4. 完成 spool 保留上限、异常恢复、目录覆盖不完整和更新迁移策略。不要为了回填数据扫描整个 Codex 历史。

必须通过的反例：

| 场景 | 通过条件 |
| --- | --- |
| A 会话在前台，B 在后台连续产生事件 | A 的显示和提醒不受 B 的事件替换 |
| 两个窗口、相同项目、多个同名会话 | 使用精确 ID 绑定；歧义时明确未知 |
| 子代理或远程任务输出更频繁 | 不将它们当成本机前台会话 |
| 数据过期、模型容量缺失、字段格式变化 | 不展示虚假的 0% 或“健康” |
| 一次压缩后迟到的旧事件到达 | 不让旧事件恢复错误警报，不伪造累计次数 |
| hook 缺 Python、被禁用、超时或磁盘写失败 | Codex 任务继续；Orb 仅呈现数据不可用 |

只有完成这些测试，才能使用“自动跟随当前会话”或“实时上下文占用”的产品描述。

## 后续：可解释提示与交接

容量提示先采用可配置规则，验证冷却、用户忽略、阈值反复跨越、会话切换与压缩后重新启用。用户应能查看提示原因，而不是面对不可解释的总分。

语义杂乱判断另立验收：建立匿名或合成标注案例，覆盖无关主题插入、目标切换、相互矛盾的旧决定，以及正常的大型单目标任务。记录误报、漏报和判断理由。完成之前只能把该能力列为研究项，不给出准确率或“智能检测”的承诺。

交接先生成可审阅的目标、约束、已验证工作、待办和引用清单。只有用户明确选择后才执行新会话操作；不自动压缩、归档、清空或中断旧会话。跨会话移交必须保留未完成目标，避免把未验证结论带入新会话。

## 后续：分发与公开审核

- 在各目标平台验收安装、更新、卸载、自动启动选择和窗口恢复。
- 完成签名、公证、发布校验和及版本兼容说明后，提供 GitHub Releases 安装包。
- 以经验证的发布者身份准备官方目录材料，核实独立桌面 app 和本地 hooks 的适用分发方式，再提交审核。

源码仓库、测试成功、安装包可下载、实际业务可用和官方目录批准是不同结果。每次发布逐项报告。详见 [分发文档](DISTRIBUTION.md)。
