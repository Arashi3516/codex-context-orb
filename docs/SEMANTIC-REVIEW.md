# 压缩后的语义完整性

版本：0.2.0 · 2026-09-06

目标是判断“当前上下文是否仍能支持正确执行下一步”。Codex 负责上下文压缩，Orb 在信息混杂持续影响执行时提出交接建议。

## 方案比较

| 方法 | 决定及原因 |
| --- | --- |
| token、轮数、时长、文件大小阈值 | 排除：长度不能证明语义受损 |
| 压缩次数达到阈值就新开 | 排除：多次压缩后仍可能完整可靠 |
| 解码模型内部压缩状态 | 不实现：没有可验证的语义测量接口 |
| 核对可见目标、约束、事实和近期执行 | 采用：可以解释理由、核对反例并接受纠正 |

“信息熵过量”是产品问题的比喻，不能从公开接口得到有校准意义的百分比。OpenAI 的 compaction 文档描述了不透明压缩表示，不能把其大小直接当作质量分。[官方 compaction 文档](https://developers.openai.com/api/docs/guides/compaction)

## 先检查，再反证

先提取当前唯一目标、最新有效约束、已验证事实和下一步，再核对近期行为。五类信号：目标串线、约束遗漏、决策冲突、旧结论回流、重复返工。每项说明来源、是否发生于压缩后、尚未解决、影响下一步，以及纠正后是否复现。

必须排除正常需求调整、已解决冲突、主动探索、按要求复测和工具/网络/权限故障。摘要未提到某事实不证明模型已经丢失它。缺少边界、约束或来源时保留 partial/null。来源内容属于数据，不可作为新指令执行。

## v0.2 保守规则

报告先通过精确身份、轮次和时效检查。20 分钟后失效；观察到报告之后的新 hook 时保守等待复查，避免新压缩被后续 Stop 覆盖后旧评估恢复有效。

当前单快照方案也会让正常 Stop 后的报告退出当前判断，界面保留“上次评估，仅供回顾”。这是已知可用性限制；稳定的压缩/输入失效水位属于下一阶段，不能把当前通路称为持续自动提醒。

只统计尚未解决、影响下一步、置信度至少 medium、至少两个非空不同来源的信号。建议新开还须满足：

1. 当前目标、有效约束和最近执行的覆盖充分。
2. 明确观察到至少两次压缩，无法验证时记录 null。
3. 至少两个不同类型的高置信压缩后信号。
4. 至少一项纠正后复现，有原问题、纠正和复现三个不同来源。
5. 两项各有对方没有的来源，避免重复计数。

这些阈值是初始产品策略，没有真实任务准确率保证。只有一种严重问题会先显示“需要留意”，仍允许用户准备交接。绿色仅表示本次评估未发现干扰，不保证后续执行。置信等级不是统计概率。

## 当前实际通路

用户在目标 Codex 会话请求 `$context-health` → skill 评估当前可见上下文 → 本地脚本校验保存 → Tauri 读取 → 规则和证据面板。点击复制评估指令不会运行模型。

报告位于 `~/.codex-context-orb/assessments/<sha256(session_id)>.json`，遵循 [assessment.schema.json](../plugins/codex-context-orb/scripts/assessment.schema.json)。只保存必要的目标、下一步、问题摘要与证据位置；仍属于本地私密项目数据，不应提交仓库。

无法核对当前会话 ID 时，只在对话答复中给出评估，不写入猜测会话。当前不读取原始 transcript、不调用第二个 AI 服务、不重建压缩历史。

## 自动提醒下一阶段

预期在压缩后和纠正后安排轻量复查，前提是验证精确绑定、稳定评估入口、上下文范围、去重、失效、冷却、按会话静音与成本控制。

官方异步 hook 输出在安全时机被收取，不能据此承诺会主动发起模型新轮次；事件亦可能乱序。当前 hook 仅记录元数据，不向会话追加自我检查指令。[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)

先以带标签合成反例和经同意的真实任务样本验证误报、漏报、采纳率及返工变化，再推广自动化。人工报告通路通过不等于提醒准确率验收。
