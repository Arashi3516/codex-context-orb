# 从任务声明到可核对的证据

版本：0.3.0 · 2026-09-06

长期目标是评估“当前上下文是否仍能支持正确执行下一步”。v0.3 实现研究设计的第一阶段：保存来源账本，核对明确选定的文件条件，并显示未知。它还不能计算上下文损坏概率或换会话收益。

## 为什么改动判断方式

长度、压缩次数、经过时间不能证明语义受损。模型自己描述“我遗漏了约束”，也不是独立证据。v0.2 的多信号、自评置信度和压缩次数规则没有真实任务校准，现已退出主动判断；旧报告只保留回顾入口。

v0.3 把有效要求、作废要求、文件版本、实际检查和评估者记录分开。声明源是评估者整理的可见要求；文件源由本地收集器读取并记录哈希。不能因为两者具有合法 schema 就声称要求完全正确或覆盖了全部原始上下文。

## 检查与状态

| 输入 | 处理 |
| --- | --- |
| active 目标、约束、事实、决策、进度 | 保留来源与关键性 |
| superseded 条目 | 保留并关联替代者，退出有效检查 |
| contains / not_contains | 对一次读取的同一份 UTF-8 文件进行字面子串检查 |
| sha256 | 核对捕获文件的字节身份 |
| manual、缺失文件或来源不确定 | unknown |
| goal_drift 等观察 | 未独立验证的记录；单凭它不显示检查失败或建议新开 |

任何有效条目的实际文件检查失败都会显示“检查未通过”，不要求累计多种问题。有失败且有未知时仍显示失败，并同时列出未知。没有失败时，范围不全、身份来源未知、假设、未决观察或未核验约束都会保留 unknown。至少有一个实际通过的文件检查，且所有有效约束和关键条目都有检查覆盖，才显示“所列检查通过”。

这只证明声明的文字/哈希条件在采集时成立。不能把标记文件包含 PASS 当作测试确实执行过的证明。期望值应来自要求或独立基线，不能从当前文件抄一个值来制造通过。[完整契约](EVIDENCE-CONTRACT.md)。

## 时间、历史与简报

报告永远是截至采集时点的收据。没有 20 分钟过期阈值，也没有压缩次数门槛。较新 hook/轮次只提示存在后续活动，不抹掉旧收据、不证明当前文件仍未变化。目标或文件改变后需要重新采集。

每会话保留最近八次收据。查看历史不会覆盖最新结果。任务简报区分声明的要求、被检查的具体文件版本、失败和未知；在原会话内纠正或用户选择的新会话中都可使用。restartBenefit 固定为 not_evaluated。

## 下一阶段的科学验证

后续需要在相同任务、模型、工具预算和评估标准下，比较当前上下文 C、当前上下文加整理状态 C+S，以及新会话加相同状态 S。先检验任务成功与返工差异，再判断是否有可归因的重启收益；不能把对新会话提供额外提示的收益全算给重启。

目前未实现这套对照实验，也没有真实 Codex 任务的误报、漏报或概率校准数据。自动后台评估需要独立完成事件触发、精确身份、范围、成本与冷却验证。
