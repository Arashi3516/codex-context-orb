# Context Orb · UI / UX

版本：0.5.0 · 2026-09-06

悬浮球提供安静入口，面板把脏度线索、上下文容量与可选压缩次数分开。核心颜色表示检查依据中的风险，外环表示有来源的容量读数；真实读数缺失时使用中性虚线环和“未接入”，不以 0% 替代。

| 状态 | 标签 | 含义 |
| --- | --- | --- |
| 青蓝液态光带 / ✓ | 所列依据一致 | 声明范围内的文件条件在采集时通过 |
| 珊瑚分叉 / ! | 发现检查偏差 | 至少一个实际检查失败 |
| 局部琥珀干扰 / ? | 疑点待核验 | 有效条目存在尚未独立验证的观察 |
| 中性灰雾 / · | 尚未评估 / 证据待补齐 | 尚无匹配报告或存在未核验条件 |

这些状态不是整个上下文的污染率，也不是模型已遗忘要求的证明。容量很高、压缩很多次，都不会改变风险颜色。真实 hook 接入目前没有可核验的上下文容量或累计压缩次数；v0.4 数值环仅在明确标注的演示数据中显示。PostCompact 只证明收到一次完成事件，不能恢复累计次数。

总览显示固定会话、独立指标、当前主动作、通过/偏差/未知数量和采集时点。详情区分字面条件、来源声明、文件 SHA-256 与未验证观察。账本保留有效、作废和假设条目及替代关系。依据一致始终限定为所列检查，换会话收益未评估。

## 交互

- 悬停或聚焦 350ms 展示被动预览，不抢焦点。单击、Enter、Space 执行当前主动作；已展开时收起。右键、Shift F10 或上下文菜单键打开详情；Escape 收起并返回球体焦点。
- 主动作经过当前能力判断：未知时准备检查，文件偏差时查看依据，待核验观察时查看线索。只有演示提供已知容量；容量紧张且依据一致时打开压缩指引。当前没有桌面任务控制连接，自动压缩、交接并续作和真实容量均明确尚未接入。
- 鼠标和键盘按下时锁定动作、任务身份与依据版本，释放前再次核对，变化时撤销。原生拖动或尺寸变更尚未完成时，不开始另一动作。
- 手动固定 A 后 B 更新不切换；暂缓提醒展示按会话隔离。
- 查看历史时明确标注历史收据，返回概览恢复最新结果。
- 网页可切换四种风险状态，另有旧方案作废场景；失败可模拟修改后重新采集。原生没有模拟检查按钮。
- 复制检查指令明确提示尚未运行。简报可编辑，按用户确认的文本精确复制。
- 未完成约束和假设继续显示未知；简报可用于原会话纠正或用户自行选择的新会话。
- 支持深浅主题、键盘焦点、减少动态效果。当前暂缓只控制界面展示，系统通知尚未实现。
- 球体动态配色默认开启，可切为中性色；状态形状与文字仍保留。液态球由代码实时绘制，形变持续流动，状态间平滑衔接；不使用图片或视频作为动画。流动效果可独立关闭，拖动、隐藏和离屏时暂停，遵循系统减少动态效果。容量环保持独立、固定起点。
- 压缩次数默认隐藏，可在设置中开启。未接入的累计次数显示“未记录”。

## 磁吸

窗口吸附三档为「仅限 Codex 窗口｜关闭｜所有窗口」，默认 Codex。拖动后松手必停靠：落点在允许吸附的可见窗口内，或球体区域触及可见边框，选择该窗口最近的边；其他位置选择当前屏幕工作区最近的边。关闭窗口吸附时始终回到屏幕边缘。没有 CLI、手动窗口绑定或屏幕吸附开关。

macOS 通过系统提供的 `com.openai.codex` bundle ID 识别 Codex。Windows 当前没有已验证的 Codex 包身份，Codex 档明确不可用；屏幕与所有窗口模式有原生实现，仍需 Windows 真机验收。

按下时保留抓取位置，位移达到 4 logical px 后才移动。拖中自由跟随，松手以 120–220 ms 的减速过渡停靠，不回弹；系统「减少动态效果」开启时直接停靠。过渡可被下一次按下中断，单击继续原停靠动作。窗口停靠只使用内侧，把完整球体限制在目标窗口与可用屏幕的交集内，靠近窗口角落时也不越界。可见区域不足以容纳完整球体时，不建立新的窗口绑定。按前后顺序选择符合设置的可见指针落点或球体触及的最近边框。前景窗口只挡住指针时，后方窗口必须另有未被遮住的边框触及球体才能选中；被覆盖的点或边框不能穿透命中。macOS Dock 的系统桌面表面不作为应用遮挡层。

已停靠时按窗口 ID 和所属进程持续跟随，只采样这一个窗口；窗口缩放保持沿边的相对位置。已绑定边框暂时越出可用屏幕时，球限制在目标的可见区域内，并保留原目标、边和相对位置；若可见区域已放不下完整球体，暂时只保证球留在屏幕内，保留绑定以便目标恢复后继续跟随。暂时没有实际边框接触时不显示假的接触状态。拖动期间暂停跟随，松手后重新绑定；目标关闭、最小化、身份改变或不再符合设置时回到屏幕。

紧凑窗口为 92×92 logical px，球按钮为 80×80，液态核心 70px、容量环外径 84px；键盘焦点轮廓保持 3px 宽、2px 外偏移，完整绘制范围为 90×90，留在原生窗口内。容量 SVG 圆环与焦点提示分别保留，不以隐藏焦点解决裁切。

拖球、有限停靠动画与静止目标检查以 60 Hz 的固定时点调度；检测到同 ID/PID 的目标移动后，以 120 Hz 采样至最后一次位置变化后 200 ms，减少跟随的轮询延迟。该频率不是屏幕渲染帧率。主线程工作时间计入周期，错过的帧跳过，不累积补帧。无跟随目标时回到 500 ms 空闲检查。原生只读取可见窗口边界、可见性与所属应用身份，不读取标题、终端、对话或截图，也不移动其他应用。

原生移动只写 Orb 自己的窗口。macOS 关闭原生窗口/背景拖动并禁止全屏平铺；Windows 清除自己的可缩放和最大化样式并刷新窗口边框，移动采用物理像素取整。系统在空闲时重定位 Orb，下一次检查会恢复原停靠位置，展开收起也使用原位置。保留 Dock/任务栏入口，不修改系统全局平铺或 Snap 设置。全屏平铺属性不能单独证明桌面拖边平铺已排除。参考：[Apple 窗口移动属性](https://developer.apple.com/documentation/appkit/nswindow/ismovable)、[Apple 全屏平铺属性](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/fullscreendisallowstiling)、[Windows 窗口样式](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-styles)、[Windows 窗口定位](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

Rectangle 的拖边识别会观察窗口位置变化，Orb 自行移动也可能被识别。使用 Rectangle 时，为 Context Orb 启用其「Ignore」选项；默认同时停止对该应用的拖边吸附。此设置由用户配置，Orb 产品代码不修改第三方设置。v0.4.3 不替换原生类方法、KVO 类链、键盘资格或事件分发。[Rectangle 官方说明](https://github.com/rxhanson/Rectangle#ignore-an-app) · [v0.95 拖动监听](https://github.com/rxhanson/Rectangle/blob/v0.95/Rectangle/Snapping/SnappingManager.swift) · [应用忽略行为](https://github.com/rxhanson/Rectangle/blob/v0.95/Rectangle/ApplicationToggle.swift)。

## 窗口与验收

原生折叠 92×92、悬停预览 320×240、详情 382×690 logical px；球体操作区 80×80，四周保留 6px 留白。停靠计算使用 92×92 球体区域。预览在同一窗口内调整尺寸后展示，极短窗口不强行显示。尺寸请求串行，尚未发送的过期请求跳过，原生手势期间推迟到结束后执行最新请求。原生拖动松手后收起详情，再选择空间更大的一侧供下次展开；展开时始终保持布局方向，避免异步换角导致球体跳位。展开、收起与设置变化保持球体位置。可用空间不足时缩小面板并保持可滚动；负坐标和 DPI 在平台坐标空间中处理。原生状态带递增序号，晚到的旧回复不能覆盖新布局。保留 Dock/任务栏入口。
