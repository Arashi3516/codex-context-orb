## 跟随调度性能

2026-09-06 以 `9d06f6a` 的实际 macOS 窗口查询代码做独立只读采样，当前显示器报告 60 Hz。原调度在主线程完成查询后再等 33 ms，周期包含队列等待、查询耗时和额外等待；本次实测约 26 Hz。

先连续采样 400 次单个目标查询，全部成功：完整查询平均 0.165 ms，p95 0.153 ms，p99 6.043 ms；单独 bundle 身份查询平均 0.023 ms，显示器工作区查询平均 0.020 ms。连续查询存在缓存效应，因此另以真实主线程队列、每次一个 ACK、同一目标窗口查询和显示器读取负载，各运行约 3 秒：

| 调度 | 样本 | 实测更新频率 | 周期间隔 p50 / p95 | 主线程读取 p95 |
| --- | ---: | ---: | ---: | ---: |
| ACK 后再等 33 ms | 80 | 26.041 Hz | 38.610 / 43.208 ms | 7.058 ms |
| 60 Hz 绝对 deadline | 181 | 59.978 Hz | 16.621 / 18.471 ms | 7.110 ms |
| 120 Hz 绝对 deadline | 347 | 115.331 Hz | 8.562 / 10.264 ms | 6.520 ms |

三组查询均无失败。依据显示器的 60 Hz 上限和定时查询负担，v0.4.3 选择 60 Hz：拖动、吸附跟随和动画采用绝对 deadline，把查询耗时计入周期；迟到时直接跳过已过期的时间槽。仍仅允许一个未完成的主线程回调，空闲 500 ms，开始操作立即唤醒。保留每次单目标身份与几何查询；当前测量不支持为省去约 0.023 ms 引入身份缓存。

新增确定性回归覆盖队列和回调耗时、迟到、精确周期边界、两天挂起、空闲切换与唤醒重置相位。采样器使用优化编译的基线平台代码，没有执行 Orb 窗口移动、WebView 渲染或真实应用主线程负载；以上频率是调度与读取实验，不能作为整应用渲染帧率或实际鼠标跟随手感通过的证据。实际手感、Windows 与多显示器仍单独验收。

后续在 v0.4.3 (`f8978c4`) 运行期间，由用户实际拖动 Codex，独立采样器只读取两个已知窗口的边界与查询时序。第一段 45 秒采样没有运动；第二段捕获实际运动。排除用户重新放置 Orb 和后来丢失绑定的片段，两段持续跟随约 1.88 秒和 0.83 秒，Codex/Orb 分别出现 96/80 和 37/28 次位置变化。按固定相对位置和采样时间中点拟合，延迟约为 19 ms 和 11 ms；短样本、8.3 ms 采样间隔与查询时间限制精度，不能从这些数字单独判定查询、主线程排队或绘制的因果占比。

v0.4.4 据此试验运动期 120 Hz：检测同 ID/PID 的目标几何变化后保持 200 ms 高速采样，连续变化续期；静止后回 60 Hz，无绑定仍 500 ms。拖球和停靠动画仍 60 Hz。真实脱离、错误、新拖动和重新绑定清除旧运动样本；首样本及不同身份不启动高速。保持单个 ACK 和迟到跳帧，原生绘制 API 未改变。新增可控时钟回归验证续期、静止不续期、精确到期、身份变化与清理，以及拖球/动画的优先级。实际延迟和手感改善仍需比较，120 Hz 采样不表示 120 FPS。

## 边界

新版收据永远对应采集时点，不再使用 v0.2 的 20 分钟或后续 Stop 失效规则。之后的活动只提示复查。来源声明不是独立宿主取证，字面检查不是行为测试，报告哈希不是防篡改的真实性证明。

本机结果不替代跨平台执行；对应提交的 macOS/Windows 框架检查与 Linux 浏览器检查以 [GitHub Checks](https://github.com/Arashi3516/codex-context-orb/actions/workflows/checks.yml) 为准。Windows 分享冲突重试与 reparse 处理有测试，但不声明能抵抗恶意并发目录替换的完整沙箱保证。

Windows 首轮 CI 暴露了两处兼容问题：Git 自动换行改变字节夹具，以及 CPython 3.12 路径查询与句柄查询的 ctime 语义不同。现对共享夹具固定 LF；同 API 的读取前后仍完整比较，跨 API 只比较文件身份、大小与修改时间。新增反例在旧实现下复现失败，修复后通过，ctime-only 变化、内容修改和文件替换仍会被拒绝。依据：[CPython 路径查询](https://github.com/python/cpython/blob/v3.12.10/Modules/posixmodule.c#L2139-L2149)、[句柄查询](https://github.com/python/cpython/blob/v3.12.10/Python/fileutils.c#L1109-L1127)、[Windows 文件时间定义](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_basic_info)。最终平台结论仍以对应提交的 CI 为准。

尚未完成：在新任务中由 `$context-health` 发起采集的完整演练（本次真实采集由主会话显式执行插件脚本）；自动语义诊断与 C/C+S/fresh+S 对照校准；后台模型复查、系统通知、前台会话自动选择；Windows 真机、多显示器、签名公证、安装升级和官方目录审核。

本机 macOS 权限完成后已验证原生报告读取与 IPC。用户已确认 v0.4.2 能吸附并跟随窗口，v0.4.3 更流畅但仍有问题，并指出 v0.4.4 的外侧停靠和轮廓裁切；当前 v0.4.5 的实际内侧吸附、触屏后恢复绑定、跟随流畅度及 Rectangle 忽略效果仍需单独确认，不能从报告界面验收推断。Windows CI 不替代 Windows 真机运行。Codex 自身界面不在本次原生控制工具允许范围内，hook review 由用户手动完成。
